# Little Light ✧

A tiny, privacy-light way to send personalised digital blessings and meaningful notes. Adjacent to the reflective ritual of Cyber Divination, without fortune-telling or claims of religious authority.

## Frozen V0.1 scope

Exactly two presets: **New Baby / Baby Shower** and **Thinking of You**. The default flow is occasion → up to five keywords/short phrases → ready-to-send card. Tappable keyword suggestions reduce typing; keywords are optional. Universal + Warm defaults, with names, an editable personal detail, all four faith perspectives and all five tones behind “Personalise.” Editable message, keepsake line, title and visual theme remain available.

Optional 15/30-second script drafts are generated **only when requested** from the keywords (or edited message when no keywords exist), with approximate spoken word budgets. The MVP uses curated phrase mappings and honest quoted fallback for unfamiliar phrases; it does not invent a shared memory from an unknown keyword. No live AI is used. The provider interface remains swappable.

Optional photo animation and camera recording run **entirely on the device**. Choose a photo for a gentle vertical zoom with a keepsake line, or explicitly request camera/microphone access to record a message. MediaRecorder exports 15/30-second MP4 or WebM depending on browser support, with early Stop and cancellation when the tab is hidden. No uploads, face animation, AI image/video generation, accounts, payments or new occasions. Photos/videos are **not included in recipient links**; users save and share media themselves. This keeps server storage and processing costs unchanged.

The default title and theme are generated by the same provider as the message. V0 uses curated templates, **not live AI**; the interface says so. `public/engine.js` exposes async `generate(input)` and `script(input,result)` methods so a future server-side LLM adapter can replace it. Keep keys server-side and explicitly disclose any future transfer of content to an LLM vendor. No per-user image generation: three Canvas-based backgrounds produce downloadable 1080×1350 cards and 1080×1920 wallpapers.

## Sharing and local media

Both sender and recipient can use **Share card**. A separate preview hides message and signature by default, uses a generic public title, and lets the user edit the keepsake line. The line can itself contain personal details, so review is explicit. File-only native sharing never sends the private bearer link, video script or hidden message. If native sharing is unavailable, Download image works instead. Available apps depend on browser/device/file format; no direct WhatsApp or Instagram posting integration is promised. Expiry/deletion cannot revoke downloaded or externally shared copies.

Photos: JPEG/PNG/WebP up to 10 MB and 25 megapixels, downscaled to at most 1440 pixels on the longest side before animation. Repainting image pixels avoids carrying original EXIF/GPS metadata into output frames. Animation is silent and generated in real time, with no vendor request. Recording permission is requested only on Record; camera and microphone tracks stop on Stop, timeout, removal/leaving, or hiding the tab. Remove clears app references/preview URLs, not files already saved or copies retained by another app. Browser/OS memory reclamation timing is outside application control.

Use HTTPS in production. MediaRecorder/canvas capture support and codecs vary. Unsupported browsers show a fallback message; use another browser or record in the phone’s camera using the short script. Physical-device and destination-app compatibility still needs a pilot. No media-content or media-use analytics were added.

## Architecture

Buildless HTML/CSS/ES modules → Cloudflare Worker with static assets → D1 for encrypted shared gifts, short-lived rate-limit buckets and aggregate daily event counts. No production dependencies and no external font, image or analytics requests. The browser holds drafts only in memory. There is no local storage or autosave.

`public/locales/en.js` holds runtime messages; `en-ui.js` is a gettext-style UI catalog with English source strings as stable keys. `i18n.js` applies the UI catalog with English fallback. For Chinese, add matching `zh.js` and `zh-ui.js` dictionaries and a Chinese content dictionary/provider; select them at the entry point and set `lang="zh"` via `translateUI`. Translate provider enum display labels while keeping the internal enum values stable. No HTML duplication or server schema change is needed. Canvas wraps by Unicode character when a word cannot fit, supporting CJK. Chinese translation and language switching are intentionally outside V0.1.

## Local run

Use a current Node LTS supported by the installed Wrangler version (Node 22+ recommended).

```sh
npm ci
npm run db:local
# Create ignored .dev.vars containing RATE_SALT="a-long-random-local-secret"
npm run dev
```

Open http://localhost:8787. A placeholder remote database ID is checked in; local D1 uses the binding and local state. If Wrangler asks for a valid ID, replace it after creating D1 as below. Sharing fails closed without DB and RATE_SALT. Never commit `.dev.vars`.

```sh
npm test
npm run check
# With local server running and migrated D1:
node test/integration.mjs
```

The integration check uses real local D1 SQL and concurrent HTTP requests. Repeated integration runs may hit the intended share limit: wait ten minutes or reset local state. Tests cover all 40 preset combinations, deferred scripts, encryption authentication, GET/HEAD safety, origin checks, atomic single redemption, analytics allowlisting and request bounds.

## Deployment

1. Create a free Cloudflare account, then `npx wrangler login`.
2. `npx wrangler d1 create little-light`; put the returned `database_id` in `wrangler.jsonc`.
3. `npx wrangler d1 migrations apply little-light --remote`.
4. `npx wrangler secret put RATE_SALT`; paste a randomly generated secret (at least 32 bytes). This salts transient abuse-limit hashes, not gift encryption.
5. `npm run deploy`. Use the returned HTTPS `workers.dev` URL; a purchased domain is optional.
6. Verify two concurrent opens, expired links, exports on iOS/Android and local analytics before inviting participants. Do not enable request-body logging, session replay or third-party trackers.

This is a standalone Cloudflare Worker project; it is not registered with Sites hosting. Deployment requires your Cloudflare account and has not been performed by merely committing the project.

## Privacy and security

- The browser encrypts the final message and optional script using a fresh AES-256-GCM key and random 96-bit IV. Only ciphertext is uploaded. The decryption key and a random 256-bit bearer token travel in the URL **fragment**, which browsers do not send to servers or link preview fetchers. The fragment is removed from visible history on recipient load and retained only in tab memory.
- D1 stores only the SHA-256 hash of the token, ciphertext and expiry. The token is generated on the server with Web Crypto. A shared link expires in seven days. Opening is an explicit same-origin JSON POST. GET/HEAD never inspect or consume gifts. `DELETE … RETURNING` makes redemption atomic and erases ciphertext immediately. Concurrent opens have one winner.
- Anyone with the complete link can redeem it. This is bearer access, not identity verification. Do not send highly sensitive information. A failed network response or wrong encryption key after redemption can lose the message; the sender must create a new link. Refreshing before opening removes the in-memory fragment, so reopen the original link. After opening, save before closing. Platform backup retention may outlast application deletion.
- Anyone holding the bearer token can explicitly delete a shared message without decrypting it using same-origin POST `/api/revoke`. The sender sees Delete beside their link; the recipient can choose Delete without opening. GET/HEAD never delete. Previously downloaded or posted copies are outside this control.
- Request bodies are bounded even without Content-Length. Exact-origin checks, JSON-only POSTs, parameterized SQL, CSP, no-referrer and nosniff headers protect the API and page. Content is rendered via text/value/Canvas APIs, never interpolated HTML.
- Basic abuse limits: ten share attempts and sixty other API attempts per ten-minute salted IP/action window. Only a salted hash is persisted, for up to about 20 minutes plus hourly cleanup. No raw IP is stored by this application. Shared networks may hit limits together. These are basic limits, not a complete anti-bot guarantee.
- Optional `TURNSTILE_SECRET` activates server verification for share requests with `botToken`, expected hostname and `action=share`. A UI widget and CSP changes must be added by the deployer before enabling that hook; it is disabled by default. No undisclosed external bot requests occur in V0.
- Application logging is disabled and code never logs content, tokens or keys. Cloudflare still processes IPs and other network metadata as hosting provider. Do not configure Logpush, traces or other tooling to record payloads.
- Hourly cron deletes expired ciphertext and rate buckets; metrics expire after 90 days. Expiry is enforced immediately during redemption, regardless of cleanup schedule.

Read [PRIVACY.md](PRIVACY.md) before public launch. These technical protections do not constitute a completed GDPR compliance assessment. Controller/contact details, lawful bases (including any special-category issue), hosting contracts/transfers, rights procedures and the final privacy notice must be completed by the operator before collecting public users’ data.

## Silent metrics and validation

The footer explains privacy without a banner or interruption. Browser events are single allowlisted names with **no properties**. Extra fields and unknown events are rejected. No names, notes, faith/tone selections, message/video text, visitor IDs, cookies or identity joins. Do Not Track and Global Privacy Control suppress browser events. Server share/redeem counts still measure successful operations without identifying visitors. Metrics are approximate, can be inflated by bots, and cannot measure unique users or repeat-user retention.

Daily metrics: `created`, `script_requested`, `card_saved`, `wallpaper_saved`, `share_created`, `redeemed`. Review with an authenticated operator-only D1 query; there is no public metrics endpoint:

```sh
npx wrangler d1 execute little-light --remote --command "SELECT day,event,count FROM metrics ORDER BY day DESC,event"
```

For a small pilot, examine download actions / creations, shares / creations and redemptions / shares (allow for seven-day delay). Count downloads as attempts, not guaranteed saves. Ask volunteers separately whether the words felt authentic, whether they edited them, and whether they would send another. Do not join feedback to tokens, faith choices or message content. Suggested exploratory goals, not claims: 50 creations, 20 saves or shares and 10 redemptions before considering paid AI. Repeat usage needs voluntary qualitative feedback; anonymous aggregates cannot establish it.

## Cost assumptions

Target **€0 cash operating cost** for a small validation pilot on Workers/D1 free plans, a free workers.dev address and no AI APIs. This is conditional on current quotas, not a guarantee. D1 currently lists 5 million rows read/day, 100,000 rows written/day and 5 GB storage on the free tier; indexed hashes and expiry avoid full scans for gift reads. Worker requests/CPU and D1 limits can stop service when exceeded. Abuse and cleanup consume operations. Check current [Workers pricing](https://developers.cloudflare.com/workers/platform/pricing/), [D1 pricing](https://developers.cloudflare.com/d1/platform/pricing/) and [static assets](https://developers.cloudflare.com/workers/static-assets/) before deployment (reviewed 2026-10-15). Do not enable paid usage without reviewing budgets. No domain, email provider, image generation, object storage or LLM credits are required.
