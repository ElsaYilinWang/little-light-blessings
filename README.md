# Little Light ✧

A tiny, privacy-light way to send personalised digital blessings and meaningful notes. Little Light helps real people express real feelings to other real people: a few personal words become a thoughtful keepsake, ready to send. It is an early-stage product being validated, not an AI companion or a memory-archive platform.

## Frozen V0.1 scope

**Minimum pilot offer:** one personalised message, one card and a matching wallpaper, with one optional founder revision. The first pilot tests sending and saving meaningful keepsakes. Optional media is experimental, is not part of pilot onboarding, and is not a condition of success. No new features are planned until the pilot produces evidence.

Three moments: **New Baby / Baby Shower**, **Thinking of You**, and **Sending wishes**. The default flow is occasion → up to five keywords/short phrases → ready-to-send card. Tappable keyword suggestions reduce typing; keywords are optional. Universal + Warm defaults, with names, an editable personal detail, all four faith perspectives and all five tones behind “Personalise.” Editable message, keepsake line, title and visual theme remain available.

Optional 15/30-second script drafts are generated **only when requested** in a conversational voice distinct from the formal card, with approximate spoken word budgets. The MVP uses curated phrase mappings and honest quoted fallback for unfamiliar phrases; it does not invent a shared memory from an unknown keyword. No live AI is used. The provider interface remains swappable.

Optional photo animation and camera recording run **entirely on the device**. Choose a photo for a gentle vertical zoom with a keepsake line, or explicitly request camera/microphone access to record a message. MediaRecorder exports 15/30-second MP4 or WebM depending on browser support, with early Stop and cancellation when the tab is hidden. No uploads, face animation, AI image/video generation, accounts, payments or new occasions. Photos/videos are **not included in recipient links**; users save and share media themselves. This keeps server storage and processing costs unchanged.

The default title and theme are generated by the same provider as the message. V0 uses curated templates, **not live AI**; the interface says so. `public/engine.js` exposes async `generate(input)` and `script(input,result)` methods so a future server-side LLM adapter can replace it. Keep keys server-side and explicitly disclose any future transfer of content to an LLM vendor. No per-user image generation: three Canvas-based backgrounds produce downloadable 1080×1350 cards and 1080×1920 wallpapers.

The script editor is beside the camera controls. A scrollable reading guide sits near the top of the live camera preview and is never burned into the recording; the captured stream is the raw camera/microphone feed. Recording drafts a script on request if none exists. An optional action copies one complete spoken sentence into the card’s keepsake line without altering the full formal message. “Write another” clears the entire previous draft, names, keywords, script and local media.

## Sharing and local media

**Recipients receive a read-only view.** Message text, title, keepsake line, signature and visual theme are displayed as sent, with no editing, script or media-production controls. Save and Share export the received content; recipient share previews do not expose title/line editors and ignore overrides. The sender's composer remains editable. Redeemed content is frozen in app state, and the backend has no gift-update endpoint. This protects the in-app experience; it cannot prevent alteration of a downloaded image in another app.

**Experimental media:** local animation and recording are retained for optional exploration. Real-device playback and destination-app compatibility are not yet verified. The core pilot deliverables are the card and wallpaper.

Both sender and recipient can use **Share card**. A separate preview always includes the full message and signature, using the current card title and keepsake line. There are no hide-content controls in this MVP. Review is explicit before sending personal details to another app. File-only native sharing never sends the private bearer link or long video script. If native sharing is unavailable, Download image works instead. Available apps depend on browser/device/file format; no direct WhatsApp or Instagram posting integration is promised. Expiry/deletion cannot revoke downloaded or externally shared copies.

Photos: JPEG/PNG/WebP up to 10 MB and 25 megapixels, downscaled to at most 1440 pixels on the longest side before animation. Repainting image pixels avoids carrying original EXIF/GPS metadata into output frames. Animation is silent and generated in real time, with no vendor request. Recording permission is requested only on Record; camera and microphone tracks stop on Stop, timeout, removal/leaving, or hiding the tab. Remove clears app references/preview URLs, not files already saved or copies retained by another app. Browser/OS memory reclamation timing is outside application control.

Use HTTPS in production. MediaRecorder/canvas capture support and codecs vary. Unsupported browsers show a fallback message; use another browser or record in the phone’s camera using the short script. Physical-device and destination-app compatibility still needs a pilot. No media-content or media-use analytics were added.

## Architecture

Buildless HTML/CSS/ES modules → Cloudflare Worker with static assets → D1 for encrypted shared gifts, short-lived rate-limit buckets and aggregate daily event counts. No production dependencies and no external font, image or analytics requests. The browser holds drafts only in memory. There is no local storage or autosave.

`public/locales/en.js` holds runtime messages; `en-ui.js` is a gettext-style UI catalog with English source strings as stable keys. `i18n.js` applies the UI catalog with English fallback. For Chinese, add matching `zh.js` and `zh-ui.js` dictionaries and a Chinese content dictionary/provider; select them at the entry point and set `lang="zh"` via `translateUI`. Translate provider enum display labels while keeping the internal enum values stable. No HTML duplication or server schema change is needed. Canvas wraps by Unicode character when a word cannot fit, supporting CJK. Chinese translation and language switching are intentionally outside V0.1.

## Privacy and security

- The browser encrypts the final message and optional script using a fresh AES-256-GCM key and random 96-bit IV. Only ciphertext is uploaded. The decryption key and a random 256-bit bearer token travel in the URL **fragment**, which browsers do not send to servers or link preview fetchers. The fragment is removed from visible history on recipient load and retained only in tab memory.
- D1 stores only the SHA-256 hash of the token, ciphertext and expiry. The token is generated on the server with Web Crypto. A shared link expires in seven days. Opening is an explicit same-origin JSON POST. GET/HEAD never inspect or consume gifts. `DELETE … RETURNING` makes redemption atomic and erases ciphertext immediately. Concurrent opens have one winner.
- Anyone with the complete link can redeem it. This is bearer access, not identity verification. Do not send highly sensitive information. A failed network response or wrong encryption key after redemption can lose the message; the sender must create a new link. Refreshing before opening removes the in-memory fragment, so reopen the original link. After opening, save before closing. Platform backup retention may outlast application deletion.
- Anyone holding the bearer token can explicitly delete a shared message without decrypting it using same-origin POST `/api/revoke`. The sender sees Delete beside their link; the recipient can choose Delete without opening. GET/HEAD never delete. Previously downloaded or posted copies are outside this control.
- Request bodies are bounded even without Content-Length. Exact-origin checks, JSON-only POSTs, parameterized SQL, CSP, no-referrer and nosniff headers protect the API and page. Content is rendered via text/value/Canvas APIs, never interpolated HTML.
- Basic abuse limits: ten share attempts and sixty other API attempts per ten-minute salted IP/action window. Only a salted hash is persisted, for up to about 20 minutes plus hourly cleanup. No raw IP is stored by this application. Shared networks may hit limits together. These are basic limits, not a complete anti-bot guarantee.
- Optional `TURNSTILE_SECRET` activates server verification for share requests with `botToken`, expected hostname and `action=share`. A UI widget and CSP changes must be added by the deployer before enabling that hook; it is disabled by default. No undisclosed external bot requests occur in V0.
- Application logging is disabled and code never logs content, tokens or keys. Cloudflare still processes IPs and other network metadata as hosting provider. Do not configure Logpush, traces or other tooling to record payloads.
- Hourly cron deletes expired ciphertext and rate buckets; metrics expire after 90 days. Expiry is enforced immediately during redemption, regardless of cleanup schedule.

Read [PRIVACY.md](PRIVACY.md) before public launch. These technical protections do not constitute a completed GDPR compliance assessment. Controller/contact details, lawful bases (including any special-category issue), hosting contracts/transfers, rights procedures and the final privacy notice must be completed by the operator before collecting public users’ data.

## Silent metrics and validation

The footer explains privacy without a banner or interruption. Browser events are single allowlisted names with **no properties**. Extra fields and unknown events are rejected. No names, notes, faith/tone selections, message/video text, visitor IDs, cookies or identity joins. Do Not Track and Global Privacy Control suppress browser events. Server share/redeem counts still measure successful operations without identifying visitors. Metrics are approximate, can be inflated by bots, and cannot measure unique users or repeat-user retention.

Daily metrics: `created`, `script_requested`, `card_saved`, `wallpaper_saved`, `share_created`, `redeemed`. Review with an authenticated operator-only D1 query; there is no public metrics endpoint:

```sh
npx wrangler d1 execute little-light --remote --command "SELECT day,event,count FROM metrics ORDER BY day DESC,event"
```

Start with **five senders**: three free learning cases (two Thinking of You, one New Baby), then offer the same bounded service to two new prospects at a stated experimental price of EUR 15. Each receives one message, a card and wallpaper, and one optional revision within two working days. The price is a hypothesis, not a validated market rate. Explain any founder review before collecting submissions; this has a different data flow from browser-only self-service drafting.

Ask about their last real attempt before showing the product: what did they send, make or buy instead? After delivery, ask which wording they changed and whether they actually sent or saved the result. Follow up after a week. Measure real acceptance of the paid offer rather than hypothetical willingness to pay. Record founder minutes and revisions to assess whether the service is sustainable.

Working continuation criteria: at least three of the five senders actually send their keepsake, and both paid prospects accept the stated offer. These are small-sample learning rules, not proof of product-market fit. If users praise but do not send it, revisit relevance; if they send but do not pay, revisit the buyer and offer before adding features. Engagement storytelling stays a separate post-MVP concierge experiment, not a third preset.

Keep only a minimal case ID, preset, founder minutes, revision count, sent/saved outcome, paid amount and reason for declining in the research tracker. Do not join these records to app tokens, faith choices or message content. Keep approved testimonials and permissions separately. Participation and public showcase permission must be separate; real names, photos and quotes are never publication requirements. Apply the operator privacy requirements in PRIVACY.md before recruitment.

Anonymous download/share/redemption counts provide secondary context only. Downloads are attempts, not guaranteed saves; redemptions may lag by seven days. These aggregates cannot establish unique-user retention, payment or recipient satisfaction.

Wallpapers are 1080×1920 artwork with only the short keepsake line, leaving the upper area free for the phone clock. No hide-message, hide-signature or text-free switches are offered. Wallpaper preview is available to senders and read-only recipients. Same-origin WebP assets are reused for previews and PNG exports; no image API runs per user. Exports wait for the image to load. Unreadably long copy produces an explicit shortening error rather than a silently truncated export. Legacy theme names still resolve. Existing links and encryption semantics are unchanged.

Artwork in public/art was generated with the built-in image tool and adapted from the approved seasonal review. These reusable assets are distributed with this project under its MIT licence; no third-party stock artwork was imported. ## Invitation-credit pilot — 21 October 2026

The creator is now invitation-only at the application layer. Cloudflare sign-in can be removed only after this version is deployed and verified. The landing page is public; entering a valid code creates a Secure, HttpOnly, SameSite=Strict functional cookie lasting at most seven days or the invitation expiry, whichever comes first. This is access control, not an account or an analytics identifier. Codes use 96 random bits, are normalized without spaces/hyphens, and only their SHA-256 hashes are stored. Do not use short human-chosen codes such as 123456. Source code and public artwork are not confidential: hiding the form is a UX gate; the server enforces gift-link creation permission and credits.

Each pilot code has three gift-link credits. Checking a code, drafting, editing, scripts, downloads, image sharing and recipient opening do not spend a credit. Only successful gift creation spends one. Copying an existing link is free; creating another link deliberately costs another credit. Deleting an existing gift does not refund it. A D1 trigger makes gift insertion, credit deduction, retry receipt and aggregate spend metrics atomic. A random client request ID and stable server-derived gift token allow retries without double charge, including after a response was lost; receipts never resurrect opened/deleted content. Receipts store ciphertext hashes, not plaintext or encryption keys, and expire with gifts. Existing gifts created before invitations still open normally.

Invitation expiry/revocation blocks new creator requests. Zero-credit codes still unlock drafting and downloads. Anyone who holds a code can spend its remaining credits; codes are not bound to a named person, and losing a code has no automatic account recovery. Recipients bypass the invitation page and never use creator credits. Gift encryption, seven-day expiry, explicit POST redemption, origin checks, rate limiting and read-only receiving remain in force. Invite attempts are limited to ten per ten-minute salted network bucket; other API/share limits still apply. Turnstile remains an optional hook, not an enabled defence. Do not treat noindex as a security control.

### Owner operations

Use Node 22+ (Node 24 for SQLite-based tests), authenticated Wrangler and the same project. There is no public administration endpoint. Apply both migrations before running the updated Worker:

    npx wrangler d1 migrations apply little-light --local
    npx wrangler d1 migrations apply little-light --remote
    node scripts/invitations.mjs issue --count 5 --credits 3 --days 30 --remote
    node scripts/invitations.mjs list --remote
    node scripts/invitations.mjs revoke ADMIN_HASH --remote
    node scripts/invitations.mjs stats --remote

The issue command prints only a file path; raw codes go into an ignored .local-private Markdown file. Never put these files, codes or functional cookies in GitHub, screenshots, analytics or public pages. Admin hashes needed to revoke codes are in that private file. Send one code per tester in a private message. Expiry and three credits are defaults for the pilot, not a pricing commitment. Owner CLI uses the Cloudflare account; customers never need one.

### Metrics and privacy

Daily aggregates now include invite_landing (browser; respects DNT/GPC), invite_accepted, invite_rejected, credit_spent, credit_blocked, share_created and redeemed, plus the existing creation/save/script events. Server-only spend and link metrics cannot be submitted by a client. Operational tables hold invitation/session hashes, remaining credits and retry receipts solely to enforce access/usage. Do not join operational hashes to behavioural events. No names, emails, faith choice, text, raw codes, tokens or encryption keys go into metrics. Accepted-code counts measure successful sessions, not unique people or unique codes; download/share clicks are not proof of delivery or retention. The browser must send only an allowlisted event name, with no extra properties. Metrics retained 90 days; session and receipt cleanup is scheduled hourly. Invitation records expire operationally and are retained for owner balance/revocation checks; no recovery identity is collected.

Self-directed use needs no extra feature: edit Sending wishes for yourself and save a card or wallpaper, without creating a link or spending a credit. Earlier intention-wallpaper ideas remain research rather than a new product branch. Business-client personalization, bulk sending and payments remain outside this pilot. The old Sites-only static preview is historical and does not enforce the current server credits; validate using the Worker version.
